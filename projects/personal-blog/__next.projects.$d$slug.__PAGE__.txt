29:Td16,<h2 id="背景与目标"><a class="heading-anchor" data-anchor-copy="true" aria-label="复制本节链接" href="#背景与目标">#</a>背景与目标</h2>
<p>长期使用的博客跑在一套需要数据库的 CMS 上：文章、标签、评论、点赞全在服务端。维护成本不在写代码，而在每次想改一个字段都要发版、迁移、备份。</p>
<p>目标很明确：<strong>内容就是文件，发布就是 push</strong>。文章、项目、友链、站点配置全部是仓库里的 Markdown 与 JSON，构建一次得到完整站点，不需要任何运行时服务。</p>
<h2 id="我负责什么"><a class="heading-anchor" data-anchor-copy="true" aria-label="复制本节链接" href="#我负责什么">#</a>我负责什么</h2>
<p>个人项目，从信息架构到实现全部由我完成：</p>
<ul>
<li>功能范围与验收标准（16 项功能、7 项横切要求）</li>
<li>设计令牌与拟态玻璃的视觉实现</li>
<li>内容层：frontmatter 校验、Markdown 渲染、代码高亮、目录提取</li>
<li>交互层：胶囊导航、搜索面板、阅读设置、分享与收藏</li>
</ul>
<h2 id="关键难点"><a class="heading-anchor" data-anchor-copy="true" aria-label="复制本节链接" href="#关键难点">#</a>关键难点</h2>
<p><strong>一、功能优先于视觉的落地顺序。</strong> 先保证 16 项功能可用，再统一成玻璃质感。实际执行时把颜色、圆角、阴影全部收敛成 CSS 变量，视觉返工只改令牌，不动组件。</p>
<p><strong>二、静态站点的边界要说清楚。</strong> 点赞计数、评论、订阅确认都需要服务端。方案是：能降级的降级（评论走 Giscus，未配置时显示只读提示），不能降级的不伪造（不显示假的阅读量与点赞数）。</p>
<p><strong>三、动效不能挡住输入。</strong> 所有入场只动 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light-default github-dark-default"><span data-line=""><span>transform</span></span></code></span> 与 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light-default github-dark-default"><span data-line=""><span>opacity</span></span></code></span>，<span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light-default github-dark-default"><span data-line=""><span>prefers-reduced-motion</span></span></code></span> 下全部取消；胶囊导航展开用弹簧，收起用短时长，避免"关不掉"的错觉。</p>
<h2 id="结果"><a class="heading-anchor" data-anchor-copy="true" aria-label="复制本节链接" href="#结果">#</a>结果</h2>
<ul>
<li>全站构建期生成，无运行时数据库</li>
<li>首屏不加载搜索索引与评论 iframe</li>
<li>深浅两套主题共用一份令牌，切换无闪烁</li>
<li>每篇文章可导出原始 Markdown</li>
</ul>
<h2 id="已知限制"><a class="heading-anchor" data-anchor-copy="true" aria-label="复制本节链接" href="#已知限制">#</a>已知限制</h2>
<ul>
<li>定时发布依赖 CI 定时重建，误差等于构建间隔</li>
<li>预览链接需要服务端鉴权，当前未实现</li>
<li>全局点赞计数未接入，仅保留本地状态</li>
</ul>
