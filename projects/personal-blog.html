个人技术博客

一个只靠构建期数据运转的静态博客，玻璃拟态界面，零服务端依赖。

#Next.js 16#React 19#TypeScript#Tailwind CSS v4#Motion

该项目暂无可公开访问的入口，未生成空按钮。

#背景与目标

长期使用的博客跑在一套需要数据库的 CMS 上：文章、标签、评论、点赞全在服务端。维护成本不在写代码，而在每次想改一个字段都要发版、迁移、备份。

目标很明确：内容就是文件，发布就是 push。文章、项目、友链、站点配置全部是仓库里的 Markdown 与 JSON，构建一次得到完整站点，不需要任何运行时服务。

#我负责什么

个人项目，从信息架构到实现全部由我完成：

  • 功能范围与验收标准（16 项功能、7 项横切要求）
  • 设计令牌与拟态玻璃的视觉实现
  • 内容层：frontmatter 校验、Markdown 渲染、代码高亮、目录提取
  • 交互层：胶囊导航、搜索面板、阅读设置、分享与收藏

#关键难点

一、功能优先于视觉的落地顺序。 先保证 16 项功能可用，再统一成玻璃质感。实际执行时把颜色、圆角、阴影全部收敛成 CSS 变量，视觉返工只改令牌，不动组件。

二、静态站点的边界要说清楚。 点赞计数、评论、订阅确认都需要服务端。方案是：能降级的降级（评论走 Giscus，未配置时显示只读提示），不能降级的不伪造（不显示假的阅读量与点赞数）。

三、动效不能挡住输入。 所有入场只动 transform 与 opacity，prefers-reduced-motion 下全部取消；胶囊导航展开用弹簧，收起用短时长，避免"关不掉"的错觉。

#结果

  • 全站构建期生成，无运行时数据库
  • 首屏不加载搜索索引与评论 iframe
  • 深浅两套主题共用一份令牌，切换无闪烁
  • 每篇文章可导出原始 Markdown

#已知限制

  • 定时发布依赖 CI 定时重建，误差等于构建间隔
  • 预览链接需要服务端鉴权，当前未实现
  • 全局点赞计数未接入，仅保留本地状态

这些限制写在文章里，也写在 README 里，不藏在代码注释中。
